# PoB2 control restyle

Repaints Path of Building 2's hand-drawn controls — softer borders, real
surface fills, calmer hover and press states, rounded corners. Pure
presentation: no layout, no sizes, no calc code touched.

Fork of PathOfBuildingCommunity/PathOfBuilding-PoE2 (MIT). Upstream is the
`upstream` remote; this work lives on the `ui-restyle` branch.

## Run it

The repo ships its own runtime, and running from the clone auto-enables Dev
Mode. Nothing to build.

```bash
cd runtime && "./Path{space}of{space}Building-PoE2.exe"
```

The `{space}` is literally part of the filename upstream — not a typo.

Edit any `.lua` under `src/`, press **F5** in the app, and it reloads in
place. That is the whole iteration loop.

| `src/Classes/ButtonControl.lua` | Every button |

| `src/Classes/DropDownControl.lua` | Every dropdown, closed and open |
| `src/Classes/EditControl.lua` | Every text field |

| `src/Classes/SliderControl.lua` | Every slider |

59 color call sites and 17 geometry call sites, all reading from one table.

### Colors

Each control draws a 1px border rect, then a fill rect inset by 1px. That
structure is untouched; only the colors moved.

| Role | Was | Now | Why |
|---|---|---|---|
| Border, resting | `0.50` | `0.28` | Hairlines at half-white on near-black read as harsh |
| Border, hover | `1.00` | `0.46` | Pure white hover was the single most dated cue |
| Border, active | `0.75` | `0.60` | Checked boxes, dragged knobs |
| Border, disabled | `0.33` | `0.16` | Disabled was brighter than it should be |
| Fill, resting | `0.00` | `0.09` | Pure black gave controls no surface at all |
| Fill, hover | `0.33` | `0.15` | Lift, not a flash |
| Fill, pressed | `0.50` | `0.05` | Press was *lighter* than hover; now it sinks |
| Field, resting | `0.00` | `0.07` | Text fields read sunken vs. raised buttons |
| Field, focused | `0.10`/`0.15` | `0.11` | Collapsed two near-identical branches |

### Corners

`DrawRoundRect(x, y, w, h, radius)` is a drop-in replacement for
`DrawImage(nil, x, y, w, h)`. It draws four corner quads sampled from the
quadrants of a white disc texture, plus three solid rects for the middle —
seven draw calls where there was one. The quads are tinted by whatever
`SetDrawColor` is live, exactly like the square version, so nothing about
the color logic changes.

The texture is a 64×64 RGBA disc with 4×4 supersampled alpha, generated by
`restyle-tooling/apply_corners.py` rather than hand-drawn. Downscaling 32px of source radius
to a 4px corner is what gives the anti-aliasing.

Radius clamps to `min(radius, width/2, height/2)`, and falls back to a plain
square rect if the radius doesn't fit or the texture fails to load — so
nothing can draw a hole.

Scrollbars get the rounded treatment on the **knob only**. The arrow buttons
and groove are 16px chrome that reads better square, and a rounded knob in a
square groove is the shape most current scrollbars use.

## Tuning

All of it is at the bottom of `src/Modules/Common.lua`:

```lua
uiStyle = {
	radius         = 4,
	border         = { 0.28, 0.28, 0.31 },
	borderHover    = { 0.46, 0.46, 0.51 },
	...
}
```

Colors are linear RGB 0..1. The slight blue bias (third channel highest)
keeps the greys from looking muddy against PoE's warm item text. `radius` is
in pixels; set it to `0` to get the square look back without reverting
anything. Change a number, hit F5, look.

## A bug this pass fixed

The first pass put `uiStyle` and `SetUIColor` in `src/Data/Global.lua`,
alongside `colorCodes`. That was wrong: `Data/Global.lua` is only reachable
through `Modules/Data.lua`, which only `Modules/Main.lua` loads — but
`src/Export/Main.lua` (the GGPK data exporter) instantiates `ButtonControl`,
`EditControl` and `DropDownControl` too, without ever loading it. Every
control draw on that path would have hit a nil global.

Both entry points load `Modules/Common.lua`, so that is where the style
table, `SetUIColor` and `DrawRoundRect` now live. `Data/Global.lua` is back
to its upstream contents.

## Re-applying after a rebase

Every script matches exact upstream text and reports failures rather than
corrupting a file, so re-run them after pulling. **Order matters** — each
later pass matches the output of the ones before it:

```bash
python -I restyle-tooling/apply_restyle.py && \
python -I restyle-tooling/apply_corners.py && \
python -I restyle-tooling/apply_shadows.py && \
python -I restyle-tooling/apply_statbar.py && \
python -I restyle-tooling/apply_breathing_room.py && \
python -I restyle-tooling/apply_hierarchy.py && \
python -I restyle-tooling/apply_layout.py && \
python -I restyle-tooling/apply_items_layout.py
```

`apply_lua51_compat.py` is independent of the others and only needed to run
the source under a stock Lua 5.1 host; see `love-host/README.md`.

All of them are idempotent. Anything that could not be matched is printed by
name; patch those by hand.

## Not done

- **Font.** Dead end for now — `runtime/SimpleGraphic/Fonts/` holds
  pre-rendered bitmap atlases (`.tga` + `.tgf` metrics) at 16 sizes per face.
  Swapping the typeface means regenerating all of them, which needs a
  generator for the `.tgf` format first.
- **Concentric corners.** The inner fill uses the same radius as the outer
  border rather than `radius - 1`, so the 1px border is very slightly thin
  at the corners. Invisible at radius 4; worth fixing if you push the radius
  higher.
- **Padding and hit targets beyond the top bar.** `uiLayout` (see below) now
  drives the top bar and side bar, but each tab's own screen still writes its
  own numbers. Of the 485 `DrawString`/`DrawImage` calls under `src/`, only
  185 are in the control classes; the other 300 are screens painting
  themselves. Those are the remaining work, and they should reference
  `uiLayout` rather than growing fresh literals.

## Layout metrics

`apply_layout.py` adds `uiLayout` to `src/Modules/Common.lua` and rewrites the
top bar and side bar to derive from it.

The problem it solves is not that coordinates were absolute — `Control.lua`
anchors are parent-relative and accept functions — but that the chrome, the
controls and the viewports they bound each carried their own copy of the same
measurement. Raising the header from 32 to 46 took four separate follow-up
fixes, every one found by looking at a screenshot rather than by reading the
code.

Declared tokens: `barHeight`, `sideBarWidth`, `rowHeight`, `gap`, `tightGap`,
`pad`, `edge`. Everything else is a function of them — `barFill()`,
`barPadY()`, `rowPitch()`, `row(n)`, `sideBarContent()`, `sideBarTop(n)`.
Set `barHeight` and the fill, the edge, the control row's centring, the tab
viewport, the side bar background and its content origin all move together.

`SnapFontSize()` lands any requested text size on one of the 16 pixel heights
the bitmap atlases actually ship (10–64, even below 28). Off-ladder sizes are
served by scaling a neighbour rather than by a hinted face — which is how the
stat bar's 11px label was quietly blurry. `ControlFontSize()` routes through
it.

`spec/System/TestLayout_spec.lua` covers the derivations, including the
property the module exists for: change `barHeight` and every dependent
measurement follows while the row rhythm does not.

### The Items tab

`apply_items_layout.py` extends the vocabulary with a second tier —
`rowDense` (20), `rowCompact` (16), `stackGap`, `hugGap`, plus `densePitch()`
and `subRowPitch()` — and puts the Items screen on it. A dense scrolling
property editor wants a smaller row than a toolbar; forcing one scale on both
would mean 24px dropdowns in a list of forty.

Items was not cramped because its coordinates were absolute — its controls
are already anchor-chained, so the pitch is derived. It was cramped because
the two halves disagreed: the equipped-slot list ran 20px rows on a 2px gap
while the editor beside it ran the same rows on a 4px gap. Both are now
`densePitch()`.

The coupling that pass removed is the section height functions. Each one
budgets its own extent as `rows * 24 + 4`, with the pitch written out by
hand — sixteen times across the file, in three different forms, two of them
buried inside a row's own `y` function. A section that reports the wrong
height clips or leaves a hole, silently. They all call `densePitch()` now.

That bug is not hypothetical: widening the gap to 4 made an affix row 20px
tall while two budgets still said 18, and nothing but reading the arithmetic
would have caught it.

`ItemSlotControl` is patched too. It takes its position as positional
arguments rather than a rect, so it needs its own handling, and its label
was drawn at `height - 4` — the one control `apply_breathing_room.py` never
reached, because it draws its label itself instead of through
`DropDownControl`.

Popup dialogs below line ~1200 are deliberately untouched: they are shared
with other tabs and have their own geometry.
